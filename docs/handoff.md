## 2. 주문 규칙 (가장 중요)

같은 규칙이 **화면(브라우저)과 DB(트리거) 양쪽**에 들어 있습니다. 화면에서 막는 것은 편의용이고, **진짜 검사는 DB가 합니다.** 화면을 고치다가 화면 쪽 검사가 빠져도 잘못된 주문이 저장되지는 않지만, 손님이 주문 버튼을 누른 뒤에야 오류를 보게 되므로 화면 쪽 검사도 유지해 주십시오.

### 2-1. 날짜·마감 (모두 한국 시간 기준)

- 픽업은 **월~금**만 됩니다. 주말은 없습니다.
- **마감 = 픽업 2일 전 밤 23:59.** 예: 금요일 픽업 → 수요일 23:59 마감. 즉 오늘 기준 **2일 뒤부터** 고를 수 있습니다.
- **최대 14일(2주) 뒤**까지만 미리 주문할 수 있습니다.
- 날짜 칸은 하루가 지나면 한 칸씩 밀립니다(월~금 → 다음 날은 화~월). 2주를 넘는 칸은 회색으로 "내일부터" / "아직 주문 전"이라고 보여 줍니다.
- 화면은 **1분마다, 그리고 탭으로 돌아올 때마다** 날짜를 다시 계산합니다. 자정이 지나면 새로고침 없이 마감된 날이 빠집니다.
- 휴무일·공휴일을 막는 기능은 **아직 없습니다.**
- 코드: `src/lib/pickup.ts` (`DEADLINE_DAYS = 2`, `PICKUP_WINDOW_DAYS = 14`), DB: `check_order_rules` 트리거.

### 2-2. 요일별 메뉴

- 빵마다 `menu_catalog.sale_days`에 판매 요일이 있습니다. 값은 `weekday`(월~목), `friday`(금) 두 가지이고, 둘 다 가질 수 있습니다.
- `sale_days`가 비어 있으면 주문 화면에 나오지 않습니다.
- 손님이 날짜를 바꾸면, 그날 메뉴에 없는 빵은 장바구니에서 **자동으로 빠지고 안내 메시지**가 뜹니다.

### 2-3. 가격·품절·재고

- **가격 0원 = "가격 준비 중"**. 메뉴에는 보이지만 담을 수 없습니다.
- `sold_out = true` 이거나 `stock = 0`이면 **품절**입니다.
- `stock`이 `null`이면 수량 제한이 없습니다. 숫자면 **주문할 때마다 그만큼 줄어듭니다.**
- ⚠️ 재고는 **날짜 구분 없이 하나의 숫자**입니다(월요일 픽업분과 금요일 픽업분이 같은 재고를 씀).
- 주문을 **취소하면 재고가 돌아옵니다.**
- 주문 금액은 **DB가 `menu_catalog`의 가격으로 다시 계산**합니다. 화면에서 보낸 가격은 쓰지 않습니다.
- 담아 둔 빵이 그사이 품절되거나 가격이 바뀌면, 장바구니가 자동으로 맞춰지고 안내 메시지가 뜹니다(`reconcileCart`, `src/lib/cart.tsx`).

### 2-4. 종류별 상한 (대량 주문 제한)

- 빵은 종류(`menu_groups`)로 묶입니다: 휘낭시에 → 쿠키 → 에그타르트 → 베이글 → 소금빵 → 치아바타.
- 종류마다 `max_qty`가 있으면 **같은 종류의 맛을 모두 합쳐** 그 수를 넘을 수 없습니다. 현재 **베이글·소금빵·치아바타는 9개**입니다.
- 넘기려고 하면 "대량 주문 안내" 문구(관리자 화면에서 편집)를 보여 주고 막습니다.

### 2-5. 주문 버튼이 막히는 순서

손님이 고칠 순서대로 하나씩 안내합니다: ① 픽업 날짜 안 고름 → ② 메뉴 불러오는 중 → ③ 종류별 상한 초과 → ④ (학부모) 학생 이름 없음 → ⑤ (학부모) 결제 방법 안 고름. 로그인하지 않았으면 주문 버튼 대신 **로그인 / 회원가입** 버튼이 나옵니다.

## 3. 손님 흐름

### 3-1. 주문하기

1. 홈 또는 메뉴에서 주문 탭으로 들어갑니다.
2. **STEP 1: 픽업 날짜 고르기.** 날짜를 누르면 메뉴 위치로 자동 스크롤됩니다. 고른 날짜는 기기에 기억됩니다(탭마다 따로).
3. **STEP 2: 빵(또는 답례품) 고르기.** 종류별로 묶여 있고, 종류 안에서는 이름순입니다. 사진이나 이름을 누르면 상세 창(`menu-detail.tsx`)이 열립니다. "인기" 표시는 관리자가 고른 최대 2개 + 실제로 가장 많이 팔린 빵 1개입니다.
4. 주문 요약(PC는 오른쪽, 휴대폰은 아래 고정 막대 → 펼치는 창)에서 수량 조절, (학부모) 학생 이름·결제 방법, (답례품) 요청사항을 입력합니다.
5. 로그인 안 했으면 로그인/회원가입으로 갔다가 **원래 주문 화면으로 돌아옵니다**(아래 3-3).
6. **주문하기 →** DB 함수 `place_order` 호출 → 성공하면 **주문 완료 창**(`order-complete.tsx`)에 픽업 날짜, 품목, 금액, **입금 계좌**(계좌이체일 때)가 나옵니다. 빵 장바구니는 비워집니다.
7. 오류가 나면 DB 오류를 손님이 이해할 수 있는 한국어로 바꿔 보여 줍니다(`orderErrorMessage`).

### 3-2. 내 주문 (`/orders`)

- 로그인 전: 로그인 화면 + "주문이 처음이신가요? 회원가입" 링크(바로 가입 화면).
- 로그인 후 위에서부터: 이름(바로 고칠 수 있음, "픽업할 때 확인할 이름") + 이메일 → **오늘 픽업** → **다가오는 주문**(가까운 날짜 순) → **지난 주문**(상태별 거르기: 전체/입금 대기/준비 중/픽업 완료/취소).
- 주문 카드 순서(사장님 손그림대로, 유지 요청): **큰 픽업 날짜 → 상태 + 진행 점 3개(입금 대기 → 준비 중 → 픽업 완료) → 품목 전부 → 합계 → 입금 대기·계좌이체면 '계좌정보' 상자(복사 버튼).**
- **입금 대기(`wait`) 상태일 때만 손님이 직접 취소**할 수 있습니다. 입금이 확인된 뒤에는 "카페에 문의해 주세요"로 막힙니다.

### 3-3. 로그인·회원가입 (`/login`)

- 이메일 + 비밀번호. 가입할 때 **이름**도 받습니다(`user_metadata.name`).
- 비밀번호 찾기 → `/reset-password`로 메일 링크.
- 구글 로그인은 켜져 있고, 카카오는 환경 변수로 꺼져 있습니다(`VITE_KAKAO_LOGIN_ENABLED`).
- **로그인 후 원래 화면으로 돌아가기:** 로그인으로 가기 전에 `localStorage`의 `edenReturnTo`에 현재 주소를 저장하고, 로그인/가입 확인 메일/구글 로그인 후 `/orders`에 도착하면 그 주소로 보냅니다(1시간 지나면 무시). `src/lib/return-to.ts`. **화면을 바꿔도 로그인 링크를 누를 때 `rememberReturnTo()`를 꼭 호출해 주십시오.**

## 4. 주문 상태 변화

`orders.status`와 `orders.payment_status` 두 칸이 있고, **트리거가 서로 맞춰 줍니다.**

```
            손님 주문
                │
        status = wait (입금 대기)          ※ 현장결제는 '주문 접수 · 현장결제'로 표시
          │                  │
   직원 "입금 확인"      손님·직원 취소
          ▼                  ▼
   status = done        status = cancelled  ← 재고 복구, 되돌릴 수 없음
   (입금 확인·준비 중)
          │
   직원 "픽업 완료"
          ▼
   status = picked
```

| status | 손님 화면 | 관리자 화면 | payment_status (계좌이체일 때) |
|---|---|---|---|
| `wait` | 입금 대기 | 입금대기 | `pending` |
| `done` | 입금 확인 · 준비 중 | 입금확인 | `confirmed` (트리거가 자동 변경) |
| `picked` | 픽업 완료 | 픽업완료 | `confirmed` |
| `cancelled` | 취소한 주문 | 취소 | 그대로 |

- 현장결제 주문은 `payment_status = 'onsite'`로 고정입니다.
- **직원은 `orders.status` 칸만 바꿀 수 있습니다**(DB 권한). 그래서 "입금 확인" 버튼은 `status='done'`으로 바꾸고, `sync_order_payment` 트리거가 `payment_status`를 처리합니다. 관리자 화면을 새로 만들 때 `payment_status`를 직접 바꾸려 하면 권한 오류가 납니다.

## 5. 관리자 기능 (`/admin`)

`staff_users` 표에 있는 계정만 들어갈 수 있습니다. 탭 6개이며, 마지막으로 연 탭을 기억합니다.

| 탭 | 기능 |
|---|---|
| **주문 · 입금** | 픽업 날짜별로 묶어서 보기(오늘 이후 기본, 지난 날은 펼쳐서), 날짜 하나만 거르기. 날짜마다 건수·입금대기 수·학부모/답례품 수 요약. 금요일은 학생 이름순(시간순으로 바꿀 수 있음). 주문마다 **입금 확인 / 픽업 완료 / 상태 직접 바꾸기 / 취소**(확인 창 띄움, 재고 복구). **1분마다·탭 복귀 시 자동 새로고침.** |
| **고객** | 고객별 이름, 이메일, 주문 수, 총 주문 금액, 자주 시킨 메뉴, 최근 주문. 검색. |
| **문의** | 문의 목록, 답변 쓰기, 답변완료 처리(`status`, `reply`만 수정 가능). |
| **메뉴** | 메뉴마다 이름·분류(베이커리/음료/답례품)·설명·**판매 요일**·**종류**·가격·수량(빈칸 = 제한 없음)·품절·**인기 메뉴 추천(최대 2개)**·사진 올리기/지우기·삭제. 여러 줄을 고친 뒤 **"변경한 메뉴 저장" 한 번으로 모두 저장**(저장 안 하고 나가면 경고). 새 메뉴 추가. 아래쪽에 **빵 종류 · 수량 제한**(종류 추가, `max_qty`). 메뉴 이름이 기본키라 같은 이름으로 바꾸면 한국어 오류 안내. |
| **글귀 · 이미지** | `site_content`의 문구와 사진 편집: 히어로, 카페소개, 핵심가치, 연혁, 오시는 길(주소·연락처), 새소식 6개, **입금 계좌(은행·계좌번호·예금주·입금 안내)와 픽업 시간**, 주문 안내(학부모 안내, 학부모 입금자명 안내, 대량 주문 안내·문의처), 개인정보처리방침, 푸터. 목록은 `CONTENT_SCHEMA`(`src/lib/site-content.ts`). |
| **관리자** | 이메일로 관리자 추가·해제, 최고 관리자 지정. **최고 관리자만** 할 수 있고, 마지막 최고 관리자는 스스로 해제할 수 없습니다. |

## 6. 데이터베이스

### 6-1. 표

| 표 | 내용 | 주요 칸 |
|---|---|---|
| `menu_catalog` | 메뉴 | `name`(기본키), `price`(0 = 준비 중), `category`(`bakery`/`drink`/`gift`), `sold_out`, `stock`(null = 무제한), `description`, `image_url`, `sale_days`, `group_name`, `is_featured`, `sort_order`(지금은 안 씀) |
| `menu_groups` | 빵 종류 | `name`, `sort_order`(화면 순서), `max_qty` |
| `orders` | 주문 | `id`, `user_id`, `items`(jsonb: 이름·가격·수량), `total`, `pickup_date`, `status`, `order_type`, `student_name`, `payment_method`(`transfer`/`onsite`), `payment_status`, `request_note`, `created_at` |
| `cart_items` | 로그인한 손님의 빵 장바구니 | `user_id`, `name`, `price`, `qty` |
| `inquiries` | 문의 | `category`, `title`, `content`, `status`(`wait`/`done`), `reply` |
| `customer_profiles` | 고객 이메일·이름 (가입 시 트리거가 자동 생성) | `user_id`, `email`, `name` |
| `staff_users` | 관리자 | `user_id`, `is_super` |
| `site_content` | 사이트 문구·사진 주소 | `key`, `value` |
| Storage `site-images` | 메뉴·사이트 사진 | 공개 읽기, 관리자만 올리기 |

모든 표에 RLS(행 단위 권한)가 켜져 있습니다. 손님은 자기 주문·장바구니·문의만 볼 수 있고, 관리자는 전부 볼 수 있습니다.

### 6-2. DB 함수 (화면에서 `supabase.rpc(...)`로 호출)

| 함수 | 하는 일 |
|---|---|
| `place_order(p_items, p_pickup_date, p_student_name, p_payment_method, p_order_type, p_request_note)` | 주문 저장. 가격 다시 계산, 재고 차감, 빵 주문이면 장바구니 비움. 반환값은 주문 id |
| `cancel_order(p_order_id)` | 손님 본인 취소 (`wait`일 때만) |
| `set_cart(p_items)` | 빵 장바구니 저장 (주문 못 하는 메뉴는 조용히 건너뜀) |
| `menu_popularity()` | 메뉴별 누적 판매량 (취소 제외) — "인기" 표시용 |
| `add_staff`, `remove_staff`, `set_staff_super`, `is_staff`, `is_super_staff` | 관리자 관리 |

### 6-3. 트리거

| 트리거 | 언제 | 하는 일 |
|---|---|---|
| `check_order_rules` | 주문 저장 전 | 2장의 규칙 전부 검사(요일, 마감, 2주, 주문 종류별 규칙, 그날 메뉴인지, 종류별 상한, 요청사항 길이). 어기면 한국어 오류로 거부 |
| `sync_order_payment` | 주문 수정 전 | `status` ↔ `payment_status` 맞추기 |
| `on_order_cancel` | 상태 수정 전 | 취소 시 재고 복구, 취소된 주문 되돌리기 금지 |
| `on_auth_user_profile` | 가입·이메일/이름 변경 후 | `customer_profiles` 갱신 |

### 6-4. 마이그레이션

- `supabase/migrations/`에 날짜 순 SQL 파일이 쌓여 있습니다. **자동으로 적용되지 않습니다.** Supabase 대시보드 → SQL Editor에 붙여 넣고 직접 실행합니다. 지금까지의 파일은 운영 DB에 모두 실행되어 있습니다.
- 디자인만 바꾸는 작업이면 DB를 건드릴 일이 없습니다.

## 7. 화면을 바꿔도 반드시 유지할 것 (체크리스트)

- [ ] 주문 화면 3종이 `place_order`에 **`p_order_type`을 올바르게** 보냄 (`village`/`parents`/`gift`).
- [ ] 날짜는 `usePickupDates()`가 주는 값만 고를 수 있음. 마감·2주 규칙을 화면에서 따로 계산하지 말고 `src/lib/pickup.ts`를 씀.
- [ ] **날짜 고르기는 주문 화면 본문 안의 첫 단계**로 둠. 따로 떠 있는 날짜 상자는 사장님이 원하지 않음.
- [ ] 날짜를 바꾸면 그날 메뉴만 보이고, 장바구니가 자동 정리됨.
- [ ] 가격 0원은 "준비 중"으로 담기 불가, 품절은 담기 불가, 남은 수량 이상은 못 담음.
- [ ] 종류별 상한(베이글·소금빵·치아바타 9개)을 넘기면 대량 주문 안내.
- [ ] 학부모 주문: 금요일만, 학생 이름 필수, 계좌이체/현장결제 선택 필수.
- [ ] 답례품: 빵과 섞이지 않는 별도 장바구니, 요청사항 입력.
- [ ] 로그인 안 한 손님은 로그인/가입 후 **보던 주문 화면으로 돌아옴** (`rememberReturnTo`).
- [ ] 주문 완료 후 입금 계좌·금액을 바로 보여 줌(계좌이체일 때). 계좌 정보는 `site_content`에서 읽음.
- [ ] 내 주문: 픽업 날짜 크게 → 상태·진행 점 → 품목 → 합계 → 계좌정보 순서, 입금 대기일 때만 취소 버튼.
- [ ] 관리자 "입금 확인"은 `status`만 바꿈(`payment_status` 직접 수정 금지).
- [ ] 관리자 주문 목록 자동 새로고침(1분·탭 복귀).
- [ ] 음료는 "매장에서만 주문"으로 표시, 담기 불가.
- [ ] **어르신용 크기 유지:** 버튼 높이 56px 이상, 본문 글자 15px 이상. 한국어가 단어 중간에서 끊기지 않게 `word-break: keep-all` 유지.
- [ ] 휴대폰에서 주문 요약은 아래 고정 막대로 항상 보이게(가리는 요소 없게).
- [ ] 고객 화면 문구는 격식체(`~입니다`, `~해 주시기 바랍니다`). FAQ의 질문과 관리자 화면은 예외.

## 8. 아직 정하지 않은 것 / 알려진 한계

- 입금한 뒤의 취소·환불 방법, 픽업 날 못 왔을 때의 처리 → 사장님 결정 대기(FAQ에 임시 문구).
- 휴무일·공휴일 막기 없음. 재고가 날짜별로 나뉘지 않음.
- 답례품의 임시 규칙(마감 2일 전, 최대 50개, 계좌이체만)은 확정 전입니다.
- 관리자 화면에서 주문번호를 손님과 맞춰 볼 방법이 아직 약합니다.
- **PR #14**(https://github.com/seyoung9089/edencafewebsite/pull/14)는 보류 중입니다. 홈 날짜 칸을 누르면 그 날짜로 주문 화면 열기(`/order?date=`), 영문 소제목 한글화, 작은 글씨 키우기, 고객 문구 격식체 정리 등이 들어 있으나 이후 변경과 충돌합니다. 필요한 부분만 새로 옮겨야 합니다.

### 파일 위치

| 무엇 | 파일 |

| 장바구니·수량 규칙 | `src/lib/cart.tsx` |
| 메뉴 불러오기·품절 판단 | `src/lib/menu.ts` |
| 사이트 문구 | `src/lib/site-content.ts` |
| 로그인 후 돌아가기 | `src/lib/return-to.ts` |
| 내 주문 | `src/routes/orders.tsx`, `src/components/my-orders.tsx` |
| 관리자 | `src/routes/admin.tsx`, `src/components/admin/*` |
| 홈 | `src/routes/index.tsx`, `src/components/hero-section.tsx` |

| 공통 스타일 | `src/styles.css` |
| DB | `supabase/migrations/*.sql`, 설정 안내 `supabase/SETUP.md` |

### 로컬 실행

```bash
npm install
npm run dev        # http://localhost:3000
```

- Supabase 주소와 공개 키가 코드에 들어 있어 `.env` 없이도 뜹니다(`.env.example` 참고).
- ⚠️ **로컬에서도 운영 DB에 연결됩니다.** 화면 확인은 괜찮지만 **실제 주문 넣기, 관리자에서 저장하기는 하지 마십시오.**
- 검사: `npx tsc --noEmit`(타입), `npm test`(테스트: `__tests__/lib/pickup.test.ts`, `cart.test.ts`, `__tests__/app/page.test.tsx`), `npm run build`. **날짜·장바구니 테스트가 통과해야** 규칙이 깨지지 않은 것입니다.

### 배포 흐름

1. `main`에서 새 브랜치를 만들어 작업합니다.
2. GitHub에 push하면 Cloudflare가 **브랜치별 미리보기 주소**(`…workers.dev`)를 PR 댓글로 달아 줍니다. 그 주소로 확인합니다(미리보기도 운영 DB를 쓰므로 주문 금지).
3. PR을 만들고 사장님이 병합하면 `main` → Cloudflare가 자동 배포합니다.
